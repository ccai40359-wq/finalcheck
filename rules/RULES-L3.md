# FinalCheck 安全规则 · L3（公司级项目）

> 用法：把本文件抄进项目根目录 `AGENTS.md`，或直接给 AI 说"按这个写"。
> 验收：`npx finalcheck audit . --tier L3`。**任何卡项未过或人工确认项未答 = 拦截，不放行**；全过出可出示的达标报告。
> 本文件 = L2 全部规则 + 下列增量。L2 的 17 条先逐条执行，再往下。

## 测试与质量（L2 基础上加码）
1. 测试覆盖率 ≥40%；核心业务流程有集成测试（Q1）
2. 无 >800 行巨型文件（超过 3 个即不达标）；重复代码块主动抽公共模块（Q3）

## 运维（L3 新增门槛）
3. 暴露 `/health` 端点（进程内含 DB 连接检查）（O2）
4. 接告警：Sentry / Prometheus / 等价物配置文件真实存在（O2）
5. Dockerfile 非 root 运行（有 USER 指令且非 root）；CI 必须含测试步骤，测试不过不许合并（O3）
6. 数据库迁移必须有 down/rollback；回滚预案写成文档（O4）
7. 备份除了脚本+调度，**恢复演练记录在案**（D2）

## 文档（与代码双向对账）
8. API 文档：OpenAPI 3.x 或 README 的 API 章节，端点必须与路由表**双向一致**——代码里删了接口文档要删，文档里写的接口代码必须真有（E1）

## 隐私与合规
9. 写一页「数据收集清单」：收集哪些个人字段、为什么、存哪、保留多久；清单必须与代码实际收集一致（D3）
10. 用户数据删除请求有实现路径（软删/硬删，写明）（D3）

## 密钥生命周期
11. 有密钥轮换流程说明（哪怕一页 md）：哪些密钥、多久轮、怎么轮（S3）
