# 可靠性修复后的能力、证据与边界

本页描述 2026-11-12 可靠性修复后的实际实现。`ACCEPTANCE.md` 仍是产品验收目标与分级矩阵的唯一事实源；本页说明**哪些目标已经落地、哪些仍有明确边界**。报告中的「过」只适用于本轮报告的档位、计划、实际执行范围和所列证据，不代表完整生产安全认证或企业合规结论。

## 执行与授权

```bash
# 默认仅静态审计，不执行被审项目的测试或质量命令
node bin/finalcheck.js audit . --tier L2
# 已确认项目可信并显式授权执行时
node bin/finalcheck.js audit . --tier L3 --run-tests
```

- `--tier L1|L2|L3`、`--json`、`--include-fixtures` 用法保持不变；`--include-fixtures` 只用于检查故意带洞的样本，默认豁免 `**/fixtures/**`。
- 默认 `runTests=false`：引擎 `audit()` 不执行 `npm test`、lint、typecheck、bench 等被审项目命令，Q1/Q2 只记录 `coverageGap`，不会静默当作已检查。
- 只有显式 `--run-tests` 才执行项目测试与质量命令；`--no-tests` 优先于 `--run-tests`，同时出现时一律禁止执行。
- 静态依赖检查可能使用受信的 npm/Git/扫描工具并联网查询 registry，但不会执行目标项目的 `npm test` 或安装脚本。
- `scan-download` 在存在 `coverageGap`（registry 失败、请求上限跳过、版本/来源未解析等）时退出码非零；高危发现同样非零，不能把「未验证」当「通过」。

## 权限边界

- `readonly` 禁止任意命令、质量命令与项目记忆写入（`remember_project` 写 `AGENTS.md` 也按写操作拒绝）。静态只读工具仍可运行。
- `workspace` 是**应用层路径策略**：限制写入范围、拦截敏感位置并叠加命令黑名单；它本身不是操作系统沙箱，不能隔离恶意代码、同机其他进程或 TOCTOU 竞争窗口。
- Windows 上 `run_command` / 质量闸可用时跑在 **dsh ACL 受限令牌沙箱**：写/删限制在 workspace 与私有 temp；**不限制读、网络、进程可见性**（这些仍靠应用层策略）。沙箱初始化任何 Win32 失败即拒绝执行；`FINALCHECK_SANDBOX=required` 时无沙箱也拒绝，否则宿主执行并返回警告。
- 受限令牌下拿不到命名管道写权限与 cygwin 共享内存：实测 `node --test` / `npm test` 静默 EPERM（退出码 1、无 stderr），Git Bash 的 `grep`/`cat`/`head` 直接 `CreateFileMapping` fatal；Codex 的 Windows 受限令牌沙箱同样报 `spawn EPERM`，这是该机制的共性而非本包缺陷。因此这类命令按兼容清单（Node 工具链、shell、cygwin 工具）改在宿主机执行并标注 `sandboxSkip`；`FINALCHECK_SANDBOX=required` 时改为拒绝。cmd / PowerShell / git / python / curl 等原生命令仍进沙箱。
- 沙箱子进程默认跑在不可见控制台（不弹黑窗）：runner 以 `CREATE_NO_WINDOW` 建控制台、受限子进程继承它。若个别系统上隐藏控制台导致受限子进程 `0xC0000142`（命令一行都没执行），工具会用可见控制台重试一次并在 stderr 写明原因。
- 目录工具和文件工具按真实路径校验：junction / 符号链接会解析到最终目标后再判断是否越出工作区；新文件会沿父目录逐级解析已有链接，坏链接不会被当作「新文件」放行。
- 审批台账按**会话 + 项目 + 工具**隔离：「本会话总是允许」不会跨会话或跨项目生效；一次性授权消费即失效。
- 质量闸的审批目标绑定 `finalcheck.quality.json` 归一化后的命令配置指纹（`目录#sha256`），并执行审批时的配置快照。配置在授权后变化需要重新审批，不能用旧授权跑新命令。
- 完全权限模式仍受路径策略与命令黑名单约束；没有 UI 审批通道、审批超时或通道故障一律按拒绝处理。

## 已实现范围

| 范围 | 当前实现 | 仍需人工核实 / 未覆盖 |
|---|---|---|
| S1 鉴权覆盖 | Express 静态路由、挂载与命名守卫；可解析的本地纯 `next()` 空守卫不算保护 | 守卫名和调用存在不能证明认证逻辑正确；跨文件守卫内部未完整证明 |
| 其他 HTTP 框架 | 检测到 Fastify/Koa/Hapi/Next server/Hono 引用时标记为不可用覆盖 | 不保证识别所有框架、所有语言或动态注册 |
| S2 注入 | 模式规则加 JS/TS 局部表达式与变量别名传播，覆盖拆行 SQL、SSRF 等常见写法 | 不含完整跨过程、跨文件、解构与重赋值数据流；告警需复核 |
| S6/S7 外部入口与属主 | 从当前路由的 AST 处理函数及可解析本地函数找验签、owner 过滤调用，排除注释与无关路由 | 不证明验签算法、返回值处理或所有权限分支正确 |
| S8 密码与会话 | 独立校验非黑名单密码算法、`httpOnly:true`、`secure:true` 与有效 `sameSite`；解析本地选项，未知值不当安全值 | 不含所有框架的会话 API；解析失败显式留缺口 |
| Q1/Q2 测试与质量命令 | 项目命令需显式授权；必填指标缺失或非法不能给过；L3 覆盖率要求本轮产物更新、有效样本总数及一致百分比 | 测试与覆盖率来自获准执行的项目，不能证明用例充分或产物不可伪造 |
| 动态探测 | 区分业务错误、SPA 外壳、匿名可访问线索；记录实际成功样本 | 匿名可访问不等于已证实越权；需要公开意图、敏感性或身份对照证据 |
| 动态证据 | 目标协议、主机、端口、基础路径/查询、会话、项目和本轮起点隔离；过期、失败、零样本不升级 | 性能/稳定/鲁棒性需要 stress 样本；一次运行不证明长期稳定 |
| 下载闸 | 保留 npm/npx 版本规格，支持 semver/tag 与 npm lockfile 版本；成功缓存按规格隔离；失败与未解析留缺口 | registry 元数据不等于 tarball 内容审计；递归限深 2、单次最多 200 次请求；不支持完整 shell、私有源与所有包管理器 |
| D2/D3 备份与隐私 | 独立校验备份条件、人工恢复记录与显式隐私字段对账，见下文 | 静态配置存在不能证明线上已部署、恢复已成功或所有采集已覆盖 |
| 其余检查 | 密钥、配置、交接、结构、可读性、静态性能、许可证、运维线索沿用现有实现 | E1 完整 API 文档双向对账、完整监控/告警/灾备闭环仍未实现；成本维度尚未接入 |

中高风险 `check` 项未解决时，L2/L3 不能给「过」；S7/S8 的启发式项保持待核实语义，不会因为降为 `check` 就自动通过。维度证据 `full` 只表示该维度要求的输入/测量已提供，不表示没有漏洞或所有业务场景已验证。

## 结论语义与 L3 适用范围

| 情况 | 结论 |
|---|---|
| 本轮计划内的卡项全部通过、无中高危待确认项、无覆盖缺口、无待授权项 | `过`（仅限本轮已覆盖范围） |
| 存在未解决的中/高危 `check` 项（含 S7/S8 启发式、人工确认项） | `修完再过` |
| 存在未过的卡项或高危实锤 | 按对应档位 `拦` / `修完再过` |
| 应跑未跑（缺 lockfile、工具失败、registry 不可达、本轮产物缺失等） | `无法验收`，报告列出实际执行关数与缺口 |
| 仅缺少 `--run-tests` 之类的授权执行项 | `待授权`，授权后重跑才能给出最终结论 |

L3 的「过」只针对本轮 11 维计划中实际执行并覆盖的检查，**不宣称完整企业合规**：测试充分性、部署状态、备份演练内容、隐私声明真实性、第三方服务行为都超出静态审计能力，需由人或独立流程确认。盖章报告必须列计划、执行关数与覆盖缺口。

## 备份与恢复证据契约

L3 的 D2 同时要求可执行备份命令、与备份关联的调度配置、近期人工恢复演练确认。只有脚本、只有 cron、只有 README 或只有保留期配置都不能满足全部条件。

在项目根保存人工确认文件 `finalcheck.evidence.json`：

```json
{
  "backupRestore": {
    "status": "confirmed",
    "checkedAt": "2026-11-12T08:00:00Z",
    "reviewer": "实际确认人",
    "evidence": "ops/restore-drill.txt"
  }
}
```

日期必须在近 90 天内（允许 5 分钟时钟偏差）；`evidence` 必须引用仓内现存、未被排除且在扫描范围内的记录。示例日期需按真实演练时间填写。该记录是人工声明，程序不自动执行恢复、不验证签名或演练内容，也不会替用户编造确认。

## 隐私字段声明契约

项目根的 `finalcheck.privacy.json` 提供显式字段集合：

```json
{ "collectedFields": ["email", "phone"] }
```

当前从可解析的 JS/TS 持久化调用对象及本地别名提取 email、phone、mobile、password、idcard、id_card、address、full_name、fullname。实现有字段而声明缺失时报 `D3.undeclared-field`；声明有字段但已覆盖代码中未找到时报 `D3.declared-field-unverified`，交给人工判断是否为未支持的写法。自然语言隐私说明不自动作为完整字段契约；明确「不收集」的简单声明与代码冲突会单独提示。动态字段、通用对象、复杂 SQL、外部服务采集仍需人工补核。

## 下载闸行为

Claude Code 下载 hook 会检查指定目标；`npm ci` / 无包名 `npm install` 检查事件工作目录。网络或解析失败、非支持来源、复杂 shell 上下文均返回未验证并以 exit 2 阻止本次安装；CLI `scan-download` 有缺口时同样返回非零。`npx --package foo tool` 检查 `foo`，不把可执行文件 `tool` 误当包名。检查使用官方 registry 元数据，不能证明自定义 npm 配置、缓存、代理或实际下载内容与官方一致，仍应结合 lockfile / integrity 与实际安装来源核实。

## 本轮验证边界

本仓库的回归依据是完整 `node:test` 套件（当前 1187 项）及桌面生产构建。源码与测试修复没有自动升级 Electron 等主要依赖，不代表已消除原依赖审计告警。真实 Electron 窗口、实际模型网关、Windows 安装包与自动更新仍需要独立的端到端验证；本文档更新不发布、不推送、不改变应用版本号（0.15.2）。
