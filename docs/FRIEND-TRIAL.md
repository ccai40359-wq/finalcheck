# FinalCheck 朋友试用说明

这份说明写给第一次接触 FinalCheck 的朋友。你不需要会写代码，照着做就能完成一次完整体检。

先说清楚：这是**内测版**，程序没有代码签名，也没有自动更新。FinalCheck 自身不会自动上传你的代码或密钥，但 AI 解读会把对话内容发到你配置的模型网关，具体见第 5 节。

---

## 1. 安装与第一次打开

1. 拿到开发者发给你的压缩包（文件名类似 `FinalCheck-0.1.0.zip`）。
2. 把压缩包**整个解压**到一个简单目录，例如 `D:\Apps\FinalCheck`。不要只把 `FinalCheck.exe` 单独拖出来，它旁边的文件也要一起保留。
3. 双击 `FinalCheck.exe`。
4. Windows 可能弹出蓝色提示「Windows 已保护你的电脑」。这是 SmartScreen 对**未签名程序**的常规提醒：
   - 点「更多信息」；
   - 再点「仍要运行」。
5. 如果杀毒软件拦截，选择「允许」或把整个 FinalCheck 目录加入信任。只运行开发者本人发给你的包，不要从陌生来源下载同名程序。

**为什么未签名**：代码签名证书需要付费并经过身份审核，内测阶段没有办理。未签名不等于有病毒，但确实意味着系统无法验证发布者，所以只信任你认识的来源。

---

## 2. 首次配置模型

FinalCheck 需要一个大模型来读懂体检结果。它支持任何「OpenAI 兼容」的网关。

1. 打开程序后，点左下角的 **Settings（齿轮图标）**。
2. 如果还没有供应商，点 **Add Provider**。
3. 填写：
   - **名称**：随便起，例如「我的网关」。
   - **Base URL**：模型服务商给你的地址，通常以 `https://` 开头、以 `/v1` 结尾，例如 `https://api.example.com/v1`。
   - **API 格式**：保持默认的 `chat-completions` 即可，除非服务商特别说明。
   - **API Key**：服务商给你的密钥，通常以 `sk-` 开头。只填在程序里，不要发到群里或写进代码。
4. 在 **模型列表** 里输入模型名（例如 `deepseek-v4.1-flash`），点 **添加模型**。列表里的第一个模型会被对话使用。
5. 点 **保存**，再点 **测试连接**。
6. 看到「已连通 · 模型已回复」就说明配置成功。失败时程序会给出原因，例如 401 是 Key 不对、404 是 Base URL 路径不对；按提示改完再点一次。

> 小提示：如果你用的是本地模型（例如 Ollama 的 OpenAI 兼容接口），Base URL 可能是 `http://127.0.0.1:11434/v1`。当前桌面版接受 http/https 地址，是否连通以「测试连接」的结果为准。

## 3. 三步体验

### 第一步：运行示例体检（L2）

开发者会给你一个**故意带洞**的示例项目 `demo-project`。它不会联网、不会启动服务，可以放心体检。

1. 在左侧 **Workspaces** 区域，点右边的「文件夹加号」图标。
2. 选择 `demo-project` 文件夹。
   - 如果示例项目在 FinalCheck 安装目录里，通常在 `resources\src\fixtures\demo-project`。
   - 如果开发者单独发了压缩包，解压后选择那个文件夹即可。
3. 点左上角 **New Session** 新建会话。
4. 在空白页点 **代码体检（Audit）** 卡片；或者在输入框里说：
   > 对当前项目做一次 L2 安全体检，结论带文件:行证据。
5. 等它跑完。你会看到一张「体检报告」卡片，最上面是结论，下面是可以展开的发现列表。

示例项目的结论通常是 **「无法验收」**，不是「拦」。原因见第 7 节：它故意没有 lockfile，依赖检查跑不了，所以报告把「没跑」如实标成缺口，而不是假装通过。

### 第二步：看懂 3 条高危

展开报告后，重点关注这 3 条红色「高危」：

1. **S1 鉴权覆盖：`GET /api/users/:id` 没有登录守卫**
   意思是：任何人只要知道地址，就能读用户资料，不需要登录。
   修法：给这个接口挂登录守卫；如果它本来就该公开，要显式登记到白名单，而不是默默放开。

2. **S2 注入：SQL 用字符串拼接**
   代码把用户输入的 `id` 直接拼进查询语句。攻击者可以构造特殊 id 读到别的数据。
   修法：改用参数化查询（占位符 `?` 或 `$1`），不要用加号或模板字符串拼 SQL。

3. **S3 密钥：硬编码 API Key**
   代码里直接写了一个看起来像真密钥的字符串。哪怕是演示值，也会被当成事故。
   修法：移到 `.env` 文件，用 `process.env.API_KEY` 读取；如果这个 Key 曾经提交到 git，要立刻作废并换新的。

这三条都是示例项目**故意埋的**，不是你的代码问题，更不要拿去部署。示例项目里还有中危项：S5 一条（CORS 允许任意来源），H1 三条（README 过短、没有启动关键词、`.env.example` 缺变量）。可以在 `DEMO-README.md` 里看到逐条对应关系。

### 第三步：体检自己的项目

1. 在 Workspaces 里添加你自己的项目文件夹。
2. 新建会话，点 **代码体检**。
3. 第一次建议先用 **L1**（个人自用项目）：只把密钥泄露当硬卡，其他问题作为提醒，压力小。
4. 如果项目有真实用户、会挂到公网，再用 **L2**：鉴权、注入、密钥、依赖、测试、交接都会检查。
5. 报告里的每条发现都有「文件:行号」证据和一段「修复提示词」。把提示词复制回 AI 对话，让它按建议改，改完再体检一次。

> **先备份或先提交 git**。体检本身只读代码，但后续让 AI 修复会改文件；有版本管理才能随时回退。

---

## 4. 报告里的四种结论

- **过**：本轮计划内的检查都通过。
- **修完再过**：没有高危实锤，但有卡项没通过，修完再复检。
- **拦**：出现高危实锤（例如硬编码密钥、未鉴权接口），建议先别上线。
- **无法验收**：有计划内的检查**没跑成**（例如缺 lockfile、没授权跑测试）。这不等于失败，也不等于通过，只表示证据不完整。

---

## 5. 数据与隐私

- **API Key** 只保存在本机：`%APPDATA%\FinalCheck\config.json`。程序不会把它发给开发者，也不会写进报告。
- **项目列表** 保存在 `%APPDATA%\FinalCheck\projects.json`，只记录你添加过哪些目录。
- **会话与体检档案** 保存在本机当前项目目录下的 `.finalcheck\` 文件夹里（会话在 `sessions\`，体检摘要和项目记忆在 `memory\`）。它们不会上传到开发者服务器。
- FinalCheck 自身不收集使用数据，没有埋点、没有自动更新、不会主动向开发者回传任何内容。
- **但请务必知道**：AI 对话功能会把你的对话内容（可能包含代码片段、文件路径）发送到你在设置里填写的 **Base URL**，也就是你选择的模型服务商。这是调用大模型必须的步骤，不是 FinalCheck 偷偷上传。请不要把无权外发的代码贴进对话；敏感项目请使用你信任的网关或本地模型。

---

## 6. 出问题怎么反馈

1. 先看程序里的红色错误提示，通常会写明原因（401 / 404 / 超时 / 模型名不对）。
2. 在左侧会话列表里**右键**出问题的会话，点 **Report issue（报告问题）**。
   - 它会复制一段诊断文本：项目路径、会话文件路径、使用的模型、上下文用量。
   - 这段文本**不包含 API Key**，可以直接粘贴给开发者。
3. 如果你的版本在 **Settings** 页有 **「导出诊断」** 按钮，也可以直接点它；导出内容同样是脱敏的，不含 Key。
4. 把诊断文本、你做了什么、看到什么现象一起发给开发者。不要发 API Key，不要发完整源码压缩包，除非开发者明确需要且你确认可以外发。

## 7. 常见疑问

**为什么显示「无法验收」？是体检失败了吗？**
不是。它表示有计划内的检查**没有跑**，证据不完整，所以程序拒绝给出「过」的结论。缺口常见于：
- 项目没有 lockfile，依赖漏洞检查无法运行；
- 桌面端默认不执行项目自己的测试，测试关记为「未授权」；
- 外部工具（如 gitleaks、osv-scanner）没安装。

缺口是「有关没跑」，不是「发现漏洞」，也不是「程序坏了」。补齐 lockfile、授权测试或装好工具后复检，缺口就会消失。

**Q1 / Q2 是什么？为什么总要授权？**
- **Q1 测试关**：要真正运行项目的 `npm test`，不是只看有没有测试文件。
- **Q2 质量命令闸**：要运行项目声明的 lint / typecheck / test / bench 命令。

运行被审项目的命令有风险（可能执行恶意脚本、可能很慢），所以桌面端默认不跑，必须你逐次授权；在 CI 里则由流水线显式开启。

**示例项目里的 Key 是真的吗？**
不是。它是以 `demo-` 开头、`...-123456` 结尾的演示假值，不对应任何真实服务。保留它只是为了演示 S3 检查会怎么报。不要在任何真实项目里这样写。

**为什么示例项目不安装依赖？**
故意的。没有依赖和 lockfile，才能演示「覆盖缺口」是什么样。体检它不需要 `npm install`，也不会联网。

**能不能体检别人的网站或项目？**
不能，除非你明确拥有或获得了书面授权。FinalCheck 是静态体检工具，不替代渗透测试授权；不要用它扫描别人的站点、接口或服务器。压测、探测功能同理，只能在你自己有权测试的目标上使用。

**会不会自动更新？**
不会。内测版没有自动更新通道。拿到新包后，解压覆盖旧目录即可；配置和会话在 `%APPDATA%` 与项目 `.finalcheck\` 里，不会因为覆盖程序而丢失（仍建议先备份）。

**报告能当安全证明吗？**
不能。它是辅助体检，可能有误报和漏报，不能替代人工审计或专业渗透测试。上线前仍需人工确认。

---

## 8. 使用边界（请务必遵守）

- 只体检**你自己拥有**或**明确获得授权**的项目。
- 不要扫描别人的网站、后台、接口或服务器；不要对未授权目标做压测或探测。
- 示例项目只用于演示，不要部署，不要改成真实服务。
- 内测程序未签名、无自动更新；只运行可信来源的包。
- AI 可能有误判，报告里的「修复提示词」只是建议，改完要自己复核并复检。
