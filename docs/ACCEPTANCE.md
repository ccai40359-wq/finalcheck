## 0. 自食其力条款

1. 本项目自身按 **L3** 标准开发：有测试、无密钥、错误处理完备、文档与实现对得上。
2. 引擎成熟后第一个白鼠 = 本仓库（跑全套 L2 检查）。
3. 本仓库违反矩阵任何 L2 条目 = bug，与用户项目同罪。

## 1. 产品定义

一句话：**人看不懂的代码，跑之前先过闸。**

- 输入：一个项目目录 + 档位（L1/L2/L3，缺省自动定档）
- 输出：体检报告——结论五态（`过` / `修完再过` / `拦` / `无法验收` / `待授权`，见 RELIABILITY.md）+ 评分卡 + 发现清单（每条带证据与修复提示词）

## 2. 分级与定档

| 档 | 一句话定义 | 力度 |
|---|---|---|
| L1 自用 | 数据丢了不心疼，只有自己用 | 唯一硬卡项=S3（密钥），其余只提醒 |
| L2 有用户 | 挂公网、有别人的数据进来 | 高危实锤拦截，卡项必修 |
| L3 公司级 | 公司项目 / 收钱 / 有合规义务 | 未达标不放行，出可出示的达标报告 |

**定档 = 先自动猜，再确认。** 自动信号（命中越多档越高）：auth/登录中间件或 user 模型 → ≥L2；依赖含支付字样 → L3；部署配置且监听 0.0.0.0 → ≥L2；都没有 → L1。

**非交互场景（CI / hook 交活闸）**：无人确认 → 取自动档 **+1 档**（保守），报告置顶提示"已保守加档，交互运行可调档"。

## 3. 判定图例、实锤与证据链

力度：`—` 不查 ｜ `提` 提醒 ｜ `查` 必查（未过写入报告）｜ `卡` 未达标触发 §5 规则

**严重度**：每条发现标 `高` / `中` / `低`。

**实锤**（§5 用词）：由**程序判定**产生（规则匹配 / 工具命中 / 文件与配置解析）的发现。**LLM 输出一律是"线索"**：线索必须被程序规则或文件证据落地后才算实锤；LLM 复核只能**豁免误报或新增线索**，不得直接产生或撤销任何 `卡` 级结论（保证 §6 可复跑）。

**每条发现必须含证据链四要素，缺一即引擎自身 bug**：

```
{ 条目ID, 严重度, 文件:行号, 判定来源(规则名/哪道关 + 原文片段), 修复提示词 }
```

## 5. 结论引擎（无歧义版）

**实锤** = 程序判定产生的发现（§3）。严重度=高 的实锤 = **高危实锤**。

| 档 | 规则 |
|----|------|
| L1 | S3 高危实锤 → `拦`；其余查项未过 → 提醒；结论 ∈ {过, 修完再过, 拦(S3)} |
| L2 | 任何 `卡` 未过 → `修完再过`；**≥1 条高危实锤 → `拦`**（含 S1/S2/S3/S4/S6/S7/S8 及 S5 升高危时） |
| L3 | 任何 `卡` 未过 → `拦`；中高风险 `check` 未确认 → `修完再过`；本轮计划内全过 → `过` + 盖章报告，但**只对本轮覆盖范围负责，不宣称完整企业合规** |

**覆盖不足封顶规则**：任何"应跑未跑"的关（Gitleaks/osv 二进制缺失、无 lockfile、LLM 网关失败、本轮 L3 产物缺失）→ 结论封顶 **`无法验收（覆盖 x/y 关）`**，禁止出 `过`；盖章报告必须列实际执行关数与实际范围。

**待授权**：默认审计只做静态检查，不执行被审项目的测试/质量命令。只有缺 `--run-tests` 这类授权执行项时，结论是 **`待授权`**（不是 `无法验收`，也不是 `拦`），报告同时给出其余检查的初判；授权后重跑才能给最终结论。`--no-tests` 优先于 `--run-tests`。

**排序铁律**：报告按严重度降序，第一条必须是最危险的。

**CLI 退出码**：`过`=0 ｜ `拦`=1 ｜ `修完再过`=2 ｜ `无法验收`=3 ｜ `待授权`=4 ｜ 用法错误=2 前置校验失败（bin 层用法错误同样非零，闸门语义进 CI）。

## 6. 引擎质量基准（打靶指标）

1. **召回**：OWASP Juice Shop 常见 10 类漏洞 v1 目标命中 **≥6 类**；打靶用 `node scripts/benchmark.mjs <目标> [tier]`（按 checkId 分布记录进 tests/benchmark/）。S6 检查项实现前为对照组不计数。打靶样本一律用第三方既有靶场（Juice Shop 本尊）——**禁止在仓库内手写带洞样本**（2026-11-07：Mimosa 钩子把 benchmark 样本当真实漏洞拦截，这是对的，样本生成不进 Write 通道）
2. **误报**：本仓库（干净基准）零高危误报；v0.x 总误报率 <50% → v1 <30% → 长期 <10%
3. **路由提取器**：单测 fixture ≥10 个（router.use 挂载、嵌套 Router、动态参数、async 中间件），全绿
4. **可复跑**：同仓库同档位连跑两次，实体发现（实锤）不得漂移；线索级允许 ±1

## 7. 环境边界

- `finalcheck.config.json` 支持 `exclude`（路径前缀数组）与 `publicRoutes`。**测试夹具、生成物目录应排除**——自食教训 #4：引擎扫自己的 tests/fixtures（故意带洞样本）报了满屏高危

- Semgrep 无原生 Windows 版：v1 用自研 AST（babel parser）+ 正则规则顶位；检测到 WSL/Docker 自动启用为增强
- Gitleaks / osv-scanner 有 Windows 原生二进制 → 必装；缺失 → 按 §5 封顶规则处理，不静默
- **v1.2 修订（白鼠迭代：二进制在本机装不上导致工具默认不可用）**：S4 判定程序改为 **npm audit（主，Node 环境必得，同一 advisory 数据源）** + osv-scanner（增强，有则并用）；S3 判定程序 = **自研规则（主判）** + gitleaks（增强，缺失仅出警告不计覆盖不足——自研 4 规则广度有限须在报告明示）。封顶规则保留给"真正跑不了的关"（无 lockfile、运行失败）
- **下载闸与 Q1/Q2 的安全边界**：X 闸场景（审外部项目）只跑静态关，**禁止执行**被审项目代码、测试或质量命令；Q1 真跑测试仅限用户自有项目并显式 `--run-tests`。CLI 审计默认 `runTests=false`，Q1/Q2 只记 `coverageGap`；`--no-tests` 优先于 `--run-tests`。桌面端 `audit_project` 固定 `runTests=false`，单独的质量闸必须走 `quality_gate` 并逐项审批。
- **未验证不是通过**：`scan-download` 存在 `coverageGap` 时退出码非零；报告里有覆盖缺口的关不得记为已检查。
- **权限边界**：`readonly` 禁止命令、质量命令与项目记忆写入；`workspace` 是应用层路径策略而非 OS 沙箱；junction/符号链接按真实路径校验；审批按会话 + 项目隔离；质量闸绑定命令配置指纹与审批时的配置快照（详见 [RELIABILITY.md](RELIABILITY.md)）。
- LLM 网关失败 → 按 §5 封顶规则，依赖 LLM 的条目标"未覆盖"，不静默
- 无 lockfile → osv 关跳过并计入覆盖不足
- 大文件（>512KB）跳过但**计入警告**不静默；非 UTF-8 编码文件本轮无嗅探（已知限制，下轮加 BOM/NUL 嗅探）
