# 电脑操控（computer-use）

用 `computer_request_access` / `computer_screenshot` / `computer_action` 三个工具操作桌面软件。核心循环只有一句话：**授权 → 确认前台 → 截图 → 一个动作 → 验证**。所有校验都是 fail-closed：任何一步不过关就停下来重新截图，绝不凭记忆或上一张图猜坐标。

## 标准循环（0.30.4 五阶段，严格按顺序）

1. **解析目标**：先确认要操作的应用（「给微信的和迪克发消息」→ 目标=微信）。不需要先看全屏。
2. **直接拍目标窗口，不要先全屏**：`computer_screenshot(target="window", window_title="微信")` 或传 `hwnd`。一次就拿到窗口完整画面 + `hwnd` + `screenshot_id` + `canAct`。窗口被别的窗口压着也拍得到（窗口捕获是「透视」的）。**返回体里已有 hwnd，不要再单独 run_command 查进程拿 hwnd**。窗口不存在就先 `run_command` 启动它（一条命令）再重试本步。
3. **连续操作复用同一张截图**：点输入框 → `type` 打字 → 点发送按钮，三步共用同一个 `screenshot_id`。坐标用**图内像素**（FC 自动换算成屏幕坐标，1:1 映射回窗口原点）。**不再需要「指针动作后强制重截」**——同一窗口内连续动作直接复用，旧截图只在窗口/焦点/布局变化时失效。
4. **结果性动作后复查「一次」就够**：发消息/保存/删除之后，用**一张** `target="window"` 截图看整段结果（气泡出来没、文字对不对）。**看一张就下结论，不要为了逐字核对连拍多张小区域**——这一步的目的是「确认结果出现」，不是「逐字验尸」。
5. **region 配额：一次任务最多 2 次**。只在确实读不清小字时用（窗口图里输入框的字模糊到无法判断），且**一张要覆盖你关心的整行文字**（width 覆盖整个输入框），不要拍 130×28 这种只框几个字的最小块。

### 什么时候才需要全屏

只有这五种：①不知道是哪个窗口（「把那个弹窗关掉」）②需要理解屏幕相对布局（「右边那个图标」）③目标已最小化（窗口捕获失败 → 全屏 + 说明）④目标是 FC 自己（Chromium 排除自进程）⑤怀疑有非应用窗口干扰（托盘/系统弹窗）。

### 需要切换前台时

`computer_action(action="focus", hwnd=…)` 被 `access` 拒绝时，错误里有 `needAccess`——**一次调用把「当前占前台的窗口」和「目标应用」一起授权**（`computer_request_access(apps=["当前前台","目标"])`），然后再 focus。不要用 Alt+Tab 或点任务栏（会被遮挡校验/时效校验拦下，真机实测浪费 6-7 次调用）。

### 权限分层与失败熔断（系统强制）

- 浏览器在前台 = read 级（只能看）；终端/IDE = click 级（只许左键）。要在网页上操作改用 browser_*，要跑命令用 run_command。
- 同一次回复里某个自动化工具失败后，后续同类调用会被自动跳过。先读失败原因再换做法，不要原样重发。

## 打字可靠性（0.30.4 实测）

- `type` 是**模拟真人逐字符输入**（每字符间隔 15ms）。中文/emoji 可用；出现疑似错字时先**截图看整段**再判断，不要连拍多张小图。
- **不要**因为一次怀疑就改用剪贴板粘贴——粘贴是绕过应用输入流程的兜底手段，仅在 `type` 真的报错时才用。
- 已知限制：微信（Qt 自绘）在中文输入法活跃时，`SendInput` 的 Unicode 直送可能被 IME 改写（实测「这」→ 逗号）。遇到就改用 `Set-Clipboard` + `Ctrl+V`，并在结果里说明走了粘贴通道。

## 复合动作（computer_sequence，0.30.4）

已验证的连续操作（同窗口、坐标都确认过、中间不需要看界面）可以一次调用做完：

```
computer_sequence { screenshot_id, steps: [
  { action: 'left_click', x, y },                 // 点输入框
  { action: 'type', text: '...' },                // 打字
  { action: 'left_click', x: sendX, y: sendY }    // 点发送
] }
```

- 上限 8 步；不含 focus/drag（focus 会换窗口让截图失效）
- **首错即停**：某步失败会告诉你前几步已生效，**不要重跑整个序列**（会重复前面的动作）
- 每小步仍走完整安全检查（权限/授权/前台/坐标/遮挡/UIA）
- 实测：三步发消息 7 次调用 / 1.1 秒（逐动作 + 每步重截是 9-10 次且中途截图失效导致失败）

## 边界与已知坑

- **权限分层（系统强制，不是建议）**：浏览器在前台 = read 级（只能看，点击/输入全被拒）；终端/IDE = click 级（只许左键，不许输入/右键/拖拽）。要在网页上操作改用 browser_* 工具（/browser-use），要在终端跑命令用 run_command——不要试图用 computer_action 绕过，会被策略直接挡下。
- **截图失效就重截**：动作报「前台窗口已变化 / 键盘焦点已变化 / 显示器布局已变化 / 截图所记录的前台窗口已变化」时，一律重新截图再继续。截图像素坐标只对那一帧有效，窗口移动、缩放、弹出对话框都会让旧坐标作废。
- **单点校验**：一个动作只改一件事，点完看结果再定下一个坐标。不要把多个坐标串成一条盲指令链连发——中途弹窗、焦点变化会让后面的全部点错位置。
- **Qt 自绘类应用（微信、部分国产软件）**：没有 UIA 控件树，界面元素全靠像素识别；窗口缩放后渲染可能不跟随 resize，旧截图上的按钮位置不可信。必须：每次缩放/弹层后重新截图再点；对「看起来是按钮」的位置先单击一次、看截图确认有反馈，再进行下一步；绝不按旧截图的坐标连点。
- **同一回复内的失败熔断**：同一次回复里某个自动化工具失败后，后续同类调用会被自动跳过并提示。先读失败原因（前台不匹配 / 坐标无效 / 权限不足），改变做法再试，而不是原样重发。
- **停止入口**：操控期间 FinalCheck 主窗口会缩成屏幕右上角的迷你窗（红色横条「FinalCheck 操控中」）。用户要中止时，点右上角迷你窗里的停止条即可恢复窗口并停止操控；告知用户这个入口，不要让用户去翻菜单。
- **适用范围**：computer_* 留给「只能靠界面点」的场景（桌面软件对话框、系统设置、没有命令行入口的 GUI）。终端与编辑器里的操作优先 run_command / 文件工具，更快也更可靠。
